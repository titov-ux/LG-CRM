# Spike Этап 0 — AI-скрининг: захват звука + латентность Whisper

Прототип по «План_AI_скрининга.docx». Проверяет два вопроса Этапа 0:

1. Работает ли захват звука вкладки Телемоста + микрофона в браузере рекрутера
   и стрим на сервер по WebSocket (два канала = готовая диаризация).
2. Укладывается ли self-hosted faster-whisper в критерий **p95 ≤ 3000 мс**
   задержки финального сегмента — и на каком железе (CPU vs GPU).

## Состав

| Файл | Что это |
|---|---|
| `capture_prototype.html` | Страница рекрутера: захват вкладки+микрофона, AudioWorklet → PCM16 16кГц → WS, живой транскрипт, детект «нет звука с вкладки» |
| `stt_server.py` | Прототип stt-service: WS-сервер, Silero VAD (офлайн, в составе faster-whisper), сегментация, распознавание, метрики латентности |
| `bench_realtime.py` | Бенчмарк без браузера: кормит WAV в реальном времени, печатает p50/p95 и вердикт по критерию |
| `gen_audio.sh` | Генерация тестового «интервью» на русском (espeak-ng), 64 с, 8 реплик с паузами |
| `interview_ru.wav` | Готовый тестовый сэмпл 16кГц mono |
| `smoke_test.js` | Автотест полного круга в headless Chromium (страница → WS → сервер → транскрипт) |

## Быстрый старт (на Mac)

```bash
cd spikes/screening
pip3 install faster-whisper websockets

# 1) Бенчмарк — главный результат этапа (модель скачается с HuggingFace, ~500МБ)
python3 bench_realtime.py interview_ru.wav --model small --cpu-threads 4
python3 bench_realtime.py interview_ru.wav --model small --no-partials      # чистый замер финалов
python3 bench_realtime.py interview_ru.wav --model medium --cpu-threads 8   # если small прошёл с запасом

# свой файл с живым голосом (точнее по качеству, espeak — робот):
# ffmpeg -i запись.m4a -ar 16000 -ac 1 my.wav && python3 bench_realtime.py my.wav --model small

# 2) Живой прототип с браузером
python3 stt_server.py --model small          # терминал 1
python3 -m http.server 8080                  # терминал 2, из этой же папки
# Chrome → http://localhost:8080/capture_prototype.html
```

**Важно:** страницу открывать только через `http://localhost` — с `file://`
AudioWorklet не загружается (проверено, AbortError).

Сценарий живого теста: открыть Телемост в соседней вкладке (можно пустую
встречу с телефоном как вторым участником), на странице прототипа нажать
1-2-3, говорить в микрофон и дать «кандидату» говорить в Телемосте.
Реплики должны появляться в транскрипте с бейджем латентности,
рекрутер и кандидат — раздельно. По «Завершить» придёт сводка p50/p95.

## Что уже проверено в облачном контейнере (2 vCPU, без сети до HF)

- Пайплайн целиком прогнан со stub-моделью (`--fake`) через headless Chromium:
  захват → WS → VAD-сегментация → события → рендер транскрипта. Работает,
  JS-ошибок нет (`node smoke_test.js`, exit 0).
- Silero VAD корректно нарезал тестовое интервью на 8 реплик с точными границами.
- Накладные расходы пайплайна без Whisper: ~0.8–1.0 с (окно тишины 600 мс +
  тик 300 мс). Значит, на распознавание остаётся ~2 с бюджета из критерия 3 с →
  **нужен RTF ≲ 0.2–0.3 на сегментах 5–10 с**.
- Модели с HuggingFace из контейнера не качаются (egress-фильтр) — реальный
  замер запускать локально/на VM по командам выше.

## Как читать результат бенчмарка

- `RTF` — офлайн-скорость: 0.25 = минута аудио за 15 с. Больше 1.0 — модель
  не успевает за речью, realtime невозможен.
- `латентность p95` — задержка финального сегмента при подаче в реальном
  времени. Включает 600 мс окна тишины VAD — это нижняя граница любой схемы.
- Вердикт `✅ ПРОХОДИТ` печатается при p95 ≤ 3000 мс (только `--speed 1`
  и реальной модели).

Матрица решения (заполнить по факту):

| Железо | Модель | RTF | p95, мс | Вердикт |
|---|---|---|---|---|
| MacBook (Apple Silicon) | small int8 | | | |
| MacBook (Apple Silicon) | medium int8 | | | |
| YC VM 8 vCPU | small int8 | | | |
| YC VM + T4 | large-v3-turbo int8_float16 | | | |

Ожидание: small на современном CPU проходит с запасом; large-v3-turbo
требует GPU, но заметно лучше держит термины/фамилии. Если small пройдёт
и качество устроит — GPU-VM на старте не нужна.

## Замечания по замерам

- Запускать только в чистом venv (`python3 -m venv .venv && source .venv/bin/activate`):
  старый torch в `~/Library/Python/3.9` роняет процесс конфликтом OpenMP (OMP Error #15).
- Partial-гипотезы — single-flight и не блокируют финалы (иначе на CPU партиалы
  выжирают воркеры и p95 финалов раздувается в разы — воспроизведено 2026-08-10).
  `--no-partials` даёт чистую нижнюю границу латентности финалов.
- Если бенчмарк печатает «⚠️ подача отставала…» — CPU не вывозит текущую
  конфигурацию, цифры латентности завышены, пробовать меньше модель/больше потоков.
- Кривой текст на `interview_ru.wav` («айксей» и т.п.) — норма: сэмпл озвучен
  роботом espeak-ng, он нужен для замера скорости. Качество распознавания
  оценивать на живом голосе (свой WAV или живой прототип с Телемостом).

## Известные ограничения прототипа (осознанно за скоупом Этапа 0)

- Нет reconnect WS и локальной страховочной записи (Этап 1–2).
- Partial-гипотезы перерисовываются грубо, без стабилизации префикса.
- `stt_server.py` держит одну сессию; пул/очередь на несколько встреч — Этап 6.
- Захват работает только в Chromium-браузерах; Телемост — во вкладке, не в приложении.
