# Cheatsheet: что доступно каждой роли

Печатная шпаргалка А4, раздаточный материал на тренинге.

## admin

- Может **всё**. Управление пользователями и правами.
- Только админ может **полностью удалить кандидата** (`?permanent=true`).
- Только админ видит **журнал аудита** (`/audit`).
- Только админ может **передать клиента** другому аккаунт-менеджеру.

## account_manager

- Видит **только тех клиентов, где он `accountManagerId`**. Это by design — изоляция между менеджерами.
- Создаёт клиентов **на себя** (не может назначить нового клиента на коллегу).
- Создаёт и редактирует вакансии своих клиентов.
- Прикрепляет кандидатов к вакансиям.
- **Не редактирует** карточки кандидатов (это рекрутер).
- **Не удаляет** клиентов (это админ).

## recruiter

- Видит все вакансии и всех кандидатов (включая чужих).
- Создаёт и редактирует кандидатов (полная карточка резюме).
- Меняет статусы кандидатов и вакансий, прикрепляет к вакансиям.
- Может архивировать кандидата с доски (но не удалить навсегда).
- **Не создаёт клиентов**.

## viewer

- Только чтение, без рейтов и контактных данных кандидатов (email/phone/rateMonth скрыты — отображаются как «—»).
- Видит аналитику, аудит — нет.

## Особые правила

- **engagement_type должен совпадать**: outstaff-вакансия принимает только outstaff-кандидата (и наоборот). Сервер вернёт ошибку 409 `engagement_type_mismatch` — UI блокирует кнопку «Прикрепить».
- **Финальные статусы вакансии** (closed, closed_success) требуют комментария при смене. Через перетаскивание канбана — запрещено, только через «Сменить статус» с комментарием.
- **Терминал** — `closed_success`. Из него обратно нельзя. `closed` можно «переоткрыть» в `in_work`.
- **Дубли кандидатов** ловятся по email и phone. Если кандидат с такими данными уже есть — 409 `duplicate_candidate` с подсказкой `existingCandidateId`.

## Полезные горячие клавиши (фронт)

- `Ctrl/Cmd + K` — глобальный поиск (если включено).
- `Esc` — закрыть модалку.
- На канбане: drag-and-drop, либо стрелочки в карточке (мобильный вариант).
